# Labeling Guidelines – BookMeBus Khmer Sentiment

**Made by our team:** HUON Sokraingsey, KHLIM Vinchhieng, HANG Lifong, UNG Seangeang (ITM 454, AUPP, Fall 2026).
We defined the labeling rules (indirect complaints, negation, mixed reviews, sarcasm, emoji-only reviews) and agreed
on the final rules after reviewing a 50-review pilot. The text was drafted with the help of Claude (see the AI-use
statement in the README).

> **Important:** the labels produced with these guidelines were generated by **Claude (Anthropic), an AI model**,
> by reading each review. They are **silver labels**, not human gold labels. Human gold labels exist only for
> the native-Khmer test set (see `gold_test_annotation_A.csv` / `gold_test_annotation_B.csv`).

## 1. What we label

Each review gets **one** of three labels, based **only on the review text**:

| Label | Meaning |
|---|---|
| `positive` | The writer is overall satisfied or praises the service. |
| `negative` | The writer is overall dissatisfied, complains, or reports a problem / bad experience. |
| `neutral` | No clear opinion (pure booking info, questions, greetings), **or** praise and complaint are about equal. |

**One simple test:** *"What would the business owner take away from this review?"*
Praise → `positive` · a problem → `negative` · nothing clear, or both about equally → `neutral`.

## 2. Hard rules

- The `score` column is **never** used to decide a label (no thresholds). Labelers do not see the score.
- Every label comes from **reading the review**. No keyword rules, no sentiment library.
- Read the original `text`. If it is written in Khmer, read the Khmer directly. If it is in another language
  (Japanese, Chinese, Russian, Korean, …), read the original. `Translation` is only used to double-check meaning.
- `text`, `score` and `Translation` are never changed.

## 3. Special cases (with real examples from the dataset)

| Case | Rule | Example → label |
|---|---|---|
| Short report of a problem | A problem is a bad experience → `negative`, even without emotion words | "Departure late 20 mins" → negative |
| Indirect / polite complaint | Counts as `negative` | "The driver should be patient. Thanks" → negative · "បើបរិយាកាសក្នុងឡានល្អជាងហ្នឹងប្រសើរណាស់" ("it would be great if the atmosphere in the bus were better than this") → negative |
| Complaint phrased as a request | `negative` | "the toilet is not comfortable, should build more room" → negative |
| Suggestion inside a happy review | Stays `positive` | "All went smoothly… maybe a small message would also help :)" → positive |
| Mixed review | Label the **main overall impression** | "Trip there went well… return was very poor, 1+ hour late, staff rude" → negative |
| Truly balanced | `neutral`, `mixed = yes` | "ការបើកបរល្អ ទៀតម៉ោង… ប៉ុន្តែ…អាហារ…ថ្លៃ 👎" (good driving & timing, but food overpriced) → neutral |
| Lukewarm + complaint/advice of similar weight | `neutral`, `mixed = yes` | "Overall services ok. But want to remind… avoid double booking… Thanks" → neutral |
| Negation | Read the whole phrase | "not bad" leans positive · "no problems at all" → positive · "not as good as expected" → negative |
| "Not bad, but …" followed by complaints | The complaints decide | "Journey was not bad, but absolutely not VIP… no wifi, no water" → negative |
| Sarcasm | Label the intended meaning | "Great, only 3 hours late. Amazing." → negative |
| Emoji-only | 👍 😊 👌 😃 → positive · 👎 😡 → negative | "👍😊" → positive |
| Resigned complaint | Still a complaint → `negative` | "Still the problem with pick ups… so I just accept it" → negative |
| Other languages | Read the original; label normally | "Рекомендую" ("I recommend") → positive |
| Unlabelable | No `label`; `exclude = yes` + `exclude_reason` | missing text, number-only ("250"), spam, meaningless text, corrupted text |

### 3b. Extra rules added after the first full pass (consistency review)

The first pass showed that some borderline patterns were labeled differently by different batches.
These rules settle them; all borderline reviews were then re-labeled by one reviewer using them.

| # | Pattern | Rule | Example → label |
|---|---|---|---|
| R1 | Praise + one problem | Problem called small / minor / "only a bit" → **positive**. Praise and problem of about equal weight → **neutral** (`mixed = yes`). Problem is about **safety** (dangerous or reckless driving, near-accident, no seat belt, driver on the phone) **or** takes up most of the review **or** the writer's overall verdict is negative → **negative**. | "Everything perfect, only minor complaint: a bit cold" → positive · "Comfy bus and nice driver but arrived 2 hours late" → neutral · "Fine, except the driver was on the phone, very unsafe" → negative |
| R2 | BookMeBus vs. bus company | Treat them as **one service**; weigh praise against complaint as in R1. | "Sam's is great. Bookmebus is shit!" → neutral |
| R3 | Problem not caused by the company (road, weather, border officials, other passengers) | If the writer clearly **excuses the company** and reports no other problem → **neutral**. Otherwise it is still a bad trip → **negative**. | "Worst trip… not because of the bus, but the road. Bus was ok." → neutral · "Couldn't rest, people in the car made noise" → negative |
| R4 | Short lukewarm words | "OK", "ok!", "all ok", "fine", "not bad" → **positive** (confidence medium). "Nothing special", "average", "so-so" → **neutral**. | "OK" → positive |
| R5 | No opinion | "No comment", "nothing", "មិនមានទេ", drop-off instructions, questions → **neutral**. | "No comment" → neutral |
| R6 | Only a name, a cut-off fragment, or meaningless text | **Exclude** (`exclude_reason = meaningless text`). | "Sereyrath", "your com" → excluded |
| R7 | Requests | A request that implies something went wrong → **negative**. A wish for a new or extra service with no complaint → **neutral**. | "The driver should be patient" → negative · "Please add more night trips" → neutral |
| R8 | Star ratings written inside the text ("4 out of 5", "10/10") | They are part of the writer's words and may be used as a hint (watch for sarcasm). The `score` column is still never used. | "best ride of my life 10/10!!" after describing 160 km/h → negative (sarcasm) |
| R9 | `mixed` flag | `mixed = yes` only for **neutral** reviews that are balanced; positive and negative reviews get `mixed = no`. | |

How the reviewers applied these rules to the remaining edge cases:
- **Safety (R1):** dangerous driving named as a problem makes the review negative even if the writer still recommends
  the trip (usually with low confidence). If the writer says they *felt safe*, it is not a safety complaint. "Fast" with no
  sign of danger is not a safety complaint on its own.
- **Lateness (R1):** a delay softened by the writer ("only", "just", "a little late") → positive; a plain delay next to
  general praise → neutral.
- **A small problem with no praise at all** ("Car a bit old") → negative (medium confidence).
- **"Thanks" / "Thank you" alone** → positive (medium). **"I didn't travel" / "I did not join"** → neutral (R5).

## 4. Columns filled for every row

| Column | Values | Meaning |
|---|---|---|
| `label` | positive / neutral / negative / empty | empty only when `exclude = yes` |
| `confidence` | high / medium / low | how sure the labeler is |
| `mixed` | yes / no | `yes` when the review has both praise and complaint of similar weight |
| `exclude`, `exclude_reason` | yes / no, text | unlabelable rows |
| `is_original_khmer` | yes / no | `yes` if the review `text` contains Khmer script (this includes code-switched Khmer–English reviews) |
| `translation_issue` | yes / no | `yes` if `Translation` is empty or has no Khmer letters, **or** if the translation clearly loses or flips the sentiment (e.g. a dropped negation); explained in `note`. We do not retranslate. |
| `note` | text | short note (language, code-switched, indirect complaint, translation problem, …) |

## 5. Data issues found during inspection

- 3 rows have no `text` (their `Translation` is a placeholder "គ្មាន។" / "មិនមាន។" = "none") → excluded.
- 2 rows have `text = "#NAME?"`: Excel turned reviews starting with `+` / `-` into a formula error, so the original
  text is lost → excluded ("original text corrupted by Excel").
- 1 row is number-only ("250") → excluded.
- 213 rows have `Translation` identical to `text` (208 Khmer reviews, 4 emoji-only, 1 number). 22 further Khmer
  reviews are code-switched; their English parts were translated in `Translation`.
- 10 reviews are written in Japanese, Chinese, Russian or Korean; they are labeled from the original.
- Some long reviews appear cut off at about 255 characters in the source data.
- Duplicate texts must get the same label.

## 6. Process

1. **Inspect** the data (summary above).
2. **Pilot**: 50 varied rows labeled and reviewed by the team; the rules above were agreed after the pilot.
3. **Full run**: the remaining rows were labeled in batches of about 100 (six labeling sessions in parallel, each
   re-reading these guidelines before every batch) and saved to `labels_progress.csv` after each batch.
4. **Consistency review**: the borderline rows (first-pass neutral, mixed, low-confidence, excluded, very short, or
   containing a contrast word such as "but") were re-labeled **blind** using rules R1–R9: one reviewer for short
   texts (≤ 40 characters), one for long texts. The review label is final (`labels_review.csv`). The keyword list
   only selected which reviews to re-read; every label was decided by reading.
5. **Final**: `scripts/finalize_labels.py` writes the outputs and runs the consistency checks (every row has a label
   or is excluded; duplicates agree; only the three allowed labels; `mixed` only on neutral rows).
